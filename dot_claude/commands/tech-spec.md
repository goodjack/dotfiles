請針對 $ARGUMENTS 功能撰寫技術工法說明文件，重點說明：

  ## 分析要求
  1. **先分析相關程式碼**：搜尋與 $ARGUMENTS 相關的檔案，理解功能實作
  2. **建立 TodoList**：規劃分析和撰寫任務進度

  ## 文件內容結構
  ### API 工法
  - Request/Response 機制：參數如何傳遞、回應格式
  - 錯誤處理：各種錯誤情況的分類和處理方式
  - 特殊機制：如冪等性、驗證邏輯等

  ### 資料庫操作機制
  - 資料表結構與用途：各表格存什麼資料、關聯關係
  - 資料操作邏輯：新增/查詢/更新的完整流程
  - 過濾和檢查機制：什麼條件觸發什麼邏輯

  ### 系統整合機制
  - 與其他功能的整合方式
  - 資料流向和處理邏輯
  - 共用模組和統一處理

  ### 環境與快取機制
  - 環境變數使用：哪些設定、對應什麼機制
  - 快取策略：是否使用快取、快取什麼資料
  - 效能考量和設計理由

  ### 錯誤處理機制
  - 錯誤分類：業務邏輯錯誤、資料完整性、異常情況
  - 處理策略：每種錯誤如何處理
  - 安全性考量：並發、重複操作等

  ## 撰寫要求
  - **專注現有機制**：不談未來規劃、技術改進、功能擴展
  - **工法導向**：說明怎麼做、為什麼這樣設計，而非程式碼細節
  - **情境完整**：涵蓋正常流程和各種異常情況
  - **分類清楚**：不同類型、種類、分類要明確說明
  - **機制邏輯**：重點在流程、邏輯、觸發條件
